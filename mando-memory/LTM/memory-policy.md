# Memory Policy

## Model: Pointer vs Depth
- Memory tool (always-injected block) = short pointers only. < 300 chars/entry.
- Vault = depth. Full reasoning, details, evidence live here.
- Pointers reference vault notes by name (e.g. "cricket source = ESPN Cricinfo; see Kalshi/learnings").

## Rules
- TOC-index: entries short pointers, depth in repo/skills/vault.
- On ceiling: raise memory_char_limit +10% (NOT before).
- Do NOT save task progress, session outcomes, completed-work logs, or TODO state to memory — use session_search for those.
- Durable facts only: user preferences, environment details, tool quirks, stable conventions.

## Procedures
- Procedures and workflows belong in skills, not memory.
- Skills that aren't maintained become liabilities — patch immediately when outdated.

## Dream Sync
- Weekly dream run extracts durable facts from sessions → vault LTM/extracted/ + auto-applies low-risk memory edits.
- Money rules, venue policy, safety bounds, standing rules → flagged for VJ approval only.
